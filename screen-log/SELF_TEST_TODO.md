# Screen Log 自测优化清单

本文记录真机自测中发现的体验问题。各项先确认方案，再按编号逐项实现和验收。

状态说明：`待处理`、`处理中`、`待验收`、`已完成`。

## 1. 日志面板改为半透明背景

**状态：待验收**

### 自测现象

切换到 `UNDERLYING_PAGE` 操作下层页面时，日志面板仍使用完全不透明的白色背景，看不到被覆盖的业务布局。虽然触摸可以透传，但视觉上无法确认正在操作的下层内容，不符合该模式的使用预期。

当前背景链路：

```text
screen_log_panel_view.xml
  -> @drawable/screen_log_panel_bg
  -> @color/screen_log_panel_bg (#FDFEFE，完全不透明)
```

### 目标体验

- 日志面板使用半透明浅色蒙层，能够看见下层页面的结构和控件。
- 日志文本、筛选器和操作控件仍保持足够的可读性。
- `LOG_PANEL` 与 `UNDERLYING_PAGE` 两种模式下视觉保持一致，触摸行为按模式区分。
- 面板边界仍清晰，避免与下层文字混在一起。

### 建议方案

- 将面板背景色改为带 Alpha 的浅色，例如先以约 80% 不透明度作为真机调试起点。
- 保留顶部边框或分隔线，帮助用户识别日志面板范围。
- 输入框、Spinner、按钮等交互控件可保持更高不透明度，避免下层内容干扰操作。
- 根据真实业务页面分别验证浅色、深色和高对比内容，最终确定 Alpha，不仅在空白测试页上判断。

### 验收标准

1. 面板覆盖区域能辨认下层按钮、列表、输入框等布局结构。
2. 日志文字、筛选条件和按钮文字仍清晰可读。
3. `UNDERLYING_PAGE` 下可一边看到控件，一边完成点击、滚动和输入。
4. `LOG_PANEL` 下滚动日志时，下层内容不会造成明显视觉干扰。
5. `1/3` 与 `2/3` 两种面板高度下表现一致。

## 2. 状态型操作使用明确的开关/选择控件

**状态：待验收**

### 自测现象

当前自动滚动使用 `Pause scroll` / `Resume scroll` 文本按钮。按钮文字描述的是“点击后执行的动作”，不是“当前状态”，用户需要反向推断当前是否暂停，容易误解。

类似问题也存在于悬浮菜单中的 `Show panel` / `Hide panel` 和 `Touch: Log` / `Touch: Page`。

### 目标体验

- 布尔状态使用 Switch，控件本身直接表达当前开关状态。
- 多选一模式使用分段按钮或单选控件，不强行套用 Switch。
- 同一个状态在面板、悬浮菜单和设置页中保持命名与取值一致。

### 建议方案

#### 自动滚动

使用 Switch，固定文案为 `自动滚动`：

```text
checked = true   当前自动跟随最新日志
checked = false  当前停留在用户浏览位置
```

替换以下入口：

- 日志面板中的 `Pause` / `Resume` 按钮。
- 悬浮菜单中的 `Pause scroll` / `Resume scroll` 菜单项。

同时新增 `记录日志` Switch，默认关闭。测试人员主动开启后持久化该状态，冷启动初始化时恢复；关闭后保留已有日志和 UI，不再接收新日志。`ScreenLogConfig.enable=false` 时该运行时开关无效，模块不记录日志也不显示面板。

#### 日志面板显示

悬浮菜单中的 `Show panel` / `Hide panel` 可改为 `日志面板` Switch：

```text
checked = true   面板当前显示
checked = false  面板当前隐藏
```

#### 触摸目标

`LOG_PANEL` / `UNDERLYING_PAGE` 是互斥模式，不是简单开启/关闭。建议使用分段选择：

```text
触摸目标  [日志面板] [下层页面]
```

设置页与悬浮菜单统一使用同一组名称。

### 验收标准

1. 用户不点击控件，也能直接判断自动滚动当前是否开启。
2. 切换自动滚动后，面板和悬浮菜单中的状态立即同步。
3. 面板显示开关与面板实际可见状态一致。
4. 触摸目标明确显示当前选中项，不使用含义模糊的动作文案。
5. Activity 切换后所有状态控件与实际状态保持一致。
